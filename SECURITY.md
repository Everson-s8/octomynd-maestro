# Security policy

## Supported versions

Security fixes target the latest `main` branch and the latest published desktop release. Older
development builds may not receive individual backports.

## Reporting a vulnerability

Please do not open a public issue for a security vulnerability. Use GitHub's private vulnerability
reporting flow from the repository's **Security** tab, or contact the maintainers privately through
the GitHub profile if that flow is unavailable.

Include:

- a short description and impact;
- affected version or commit;
- reproducible steps or a minimal proof of concept;
- any mitigation you have identified.

Do not include live provider keys, Telegram bot tokens, OAuth artifacts, personal paths, databases,
or private logs in the report. If a credential was exposed, revoke it immediately before reporting.

The maintainers will acknowledge a valid report, investigate it privately, and coordinate a fix or
mitigation before public disclosure when practical.
