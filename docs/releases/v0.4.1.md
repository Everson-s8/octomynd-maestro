# Maestro v0.4.1

## Highlights

- Grants autonomous task execution only inside the task's governed worktree,
  with explicit, persisted workspace consent.
- Adds deterministic validation for Python projects, including virtual
  environment-aware test discovery and Python compile checks.
- Improves Goal recovery and provider handoff while preserving useful context;
  retries the current provider before moving to another eligible provider.
- Discovers project structure from tracked and non-ignored files, and limits
  dependency preparation to project roots and validation targets instead of
  installing every manifest found in examples, fixtures, or generated builds.
- Makes the packaged CLI share the desktop app's data directory and brings its
  chat terminal closer to the supplied Maestro terminal design.
- Covers desktop update-badge states with focused UI regression tests and
  improves spacing between connected providers and the connect-provider action.

## Validation status

Built on 2026-09-24 from `main` at the v0.4.1 release candidate, after PRs
#213 and #214 were merged. With Node 24.19.0 and Electron 43.4.1:

- `npm ci` completed; npm reported 0 vulnerabilities.
- `npm run typecheck` and `npm run typecheck:ui` passed.
- `npm test -- --maxWorkers=2` passed: 91 files, 878 tests.
- `npm run release:win` produced the Windows installer and update metadata.
- `npm run verify:release` confirmed the installer, `.blockmap`, and
  `latest.yml` all declare and reference v0.4.1.
- CI for PRs #213 and #214 passed on Windows and Ubuntu, including typechecks,
  tests, UI build, and secret scan.

Known build notices: the UI bundle exceeds Vite's 500 kB advisory threshold,
Electron Builder reports `asar` disabled, and the installer is unsigned
(`Get-AuthenticodeSignature`: `NotSigned`). These are documented limitations,
not test failures.

## Client update acceptance

The actual installed-client update from v0.4.0 to v0.4.1 has **not yet been
verified**. A successful package build and local artifact check do not prove
that an installed client discovers the release, downloads it, restarts, and
preserves its user data. Verify these steps on a v0.4.0 installation before
calling the update path validated:

- [ ] The installed app reports v0.4.0 and discovers v0.4.1 from the
      production GitHub Releases feed.
- [ ] The app clearly indicates the update is available and exposes the
      expected download/state controls.
- [ ] Download progress reaches the ready-to-restart state.
- [ ] Restart relaunches Maestro at v0.4.1 without a manual installer run.
- [ ] Existing projects, provider connections, chat history, and settings
      remain present.
- [ ] A failed update leaves the app usable and provides a retry/manual-install
      path.

Record the source and target versions, artifact URLs, and outcome here after
the client test. Do not describe automatic updating as verified until then.

## Distribution

The unsigned beta can be distributed through GitHub Releases. Publish all three
update artifacts together; uploading only the `.exe` breaks `electron-updater`
because clients cannot find `latest.yml`:

- `Maestro-Setup-0.4.1-x64.exe` — 119,737,169 bytes
- `Maestro-Setup-0.4.1-x64.exe.blockmap` — 122,278 bytes
- `latest.yml` — 351 bytes
- Installer SHA-256: `e93b7aaa9aa7d35395ac046b73404d9e7fdaaa083952605542e691999f15678c`

These artifacts are locally built from the current `main`; they have not been
uploaded. Users should download only from the repository's Releases page and
verify the checksum before running the unsigned installer.
