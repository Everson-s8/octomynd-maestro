# Maestro v0.3.6

## Highlights

- Chat recovery now interprets explicit and contextual requests such as
  “desbloquear”, “tentar novamente” and follow-ups like “acho que agora você
  consegue”, then resumes the matching Goal when the target is unambiguous.
- Goal execution preserves checkpoints across provider failures, attempts a
  safe worktree-permission repair, and routes recoverable failures to a
  fallback provider or waiting state instead of losing the work.
- Chat process activity is scoped to the live request, preserves the user's
  reading position, avoids duplicate managed servers, and supports guidance
  for an active Goal.
- Task intake and Goal/review prompts now require stronger evidence for
  persistence, mock/fixture, startup, UI, and existing-state validation.
- Added the governed Product Design Skill with deterministic focus matching,
  design-contract guidance, and rendered-state evidence requirements.
- Human review approval no longer requires an artificial justification when
  the change-safety gate has passed.

## Validation

- Backend and UI typechecks passed.
- Local test suite passed after rerunning the transient repository-sync test.
- GitHub Actions passed on Ubuntu and Windows.
- Windows installer build remains unsigned; verify the SHA-256 checksum before
  distributing the installer.

## Distribution

Build the installer with `npm run release:win`, then publish
`release/Maestro-Setup-0.3.6-x64.exe` to the GitHub Release together with its
SHA-256 checksum.
